# Changelog

## Unreleased

- **Task create and edit pages** (#427).
  - `/tasks/new` and `/tasks/:id/edit` are one form: the goal, where it runs (machine and browser profile), the agent policy, safety (allowed sites, ask before purchases) and schedules. Save stores the task and its schedules together.
  - "Save and run now" saves, starts a run and opens it. A value the server refuses is shown on its field.
  - `/tasks/new?goal=` starts from a goal and `/tasks/new?from=<task id>` from a copy of a task, with its schedules paused.
  - Leaving with unsaved changes asks first.
- **Responsive pass** (#431).
  - Phone navigation: the bottom bar is Home, Inbox, Tasks, Runs. Fleet, Settings and Administration are in the user menu. Inbox shows the number of pending questions on the bar, the rail and the tab title.
  - Fleet: profile actions are icon buttons, or one menu on a phone. The enrollment dialog is full screen on a phone, with a Copy button that confirms.
  - Desktop viewer: fills the window without page scroll, with Fit and Actual size, a Keyboard button, Full screen where the browser has it and a rotate hint.
  - Run page: two panes on wide screens while the run is live; one column on a phone with Cancel, Watch and Take over in a bar above the navigation.
  - `npm run ui:screens` checks every route at five widths in light and dark for horizontal scroll. The README has a "Responsive rules" section.
- **Schedule editor** (#425).
  - A schedule is built from choices: every N minutes, every N hours, daily at one or more times, weekly on chosen days, monthly on chosen days, or Advanced for a cron expression. The stored value is still a 5-field cron expression.
  - The editor shows the schedule as a sentence and its next runs before saving.
  - The time zone defaults to the profile's. A schedule in another zone shows a hint with a one-click update.
  - A schedule can now be edited, not only added and deleted. The policy override stays.
- **Inbox and question form** (#429).
  - Fixed: labels no longer sit over the text above the field or get cut on a phone; long options wrap inside the card; the number field has no spinner between the value and its unit; the action buttons stack full width on a phone with Decline last.
  - A secret can be shown while typing. It hides again on submit, when the tab is hidden and after 30 seconds without typing.
  - Each request shows a live countdown and a thumbnail of the run's browser. An answered card says "Sent." and then leaves the list.
  - Declining a request that a browser session is waiting on asks first.
- **Delete runs** (#421).
  - `DELETE /runs/:id` deletes one finished run. `POST /runs/delete` deletes by ids or by a filter and returns how many were deleted, their cost and which were skipped because they are live.
  - A filter that matches more than 500 runs is deleted by a queue job. Deleting every finished run requires the expected count, and the request fails if the match has changed by more than 5%.
  - A live run (queued, running or waiting for a person) is never deleted.
  - New permission `runs:delete`, granted to contributors and organization admins. Existing databases get it from `prisma:seed`.
- **Tasks API: summaries, paging, schedules with the task, preview, pause and resume** (#424).
  - `GET /tasks?envelope=1&include=summary` pages tasks with search, filters (`scheduled`, `paused`, `unscheduled`, `failing`, `never_run`, by policy) and sorts. Each item carries its schedules, schedule state, next run, last run, live run, run counts and resolved policy, from a fixed number of queries per page.
  - `POST /tasks` accepts `schedules[]` and creates the task and its schedules in one transaction. `PUT /tasks/:id/schedules` replaces a task's schedules.
  - `POST /tasks/:id/schedules/pause` and `/resume` switch all of a task's schedules.
  - `GET /tasks/:id/stats` returns totals, success rate, durations, cost and a daily series.
  - `POST /schedules/preview` validates a cron expression and returns a sentence and the next firings. `GET /schedules/defaults` returns the time zone a new schedule gets.
  - A schedule's time zone is optional and defaults to the profile's. Schedule responses carry a `description`.
- **Console UI foundation** (#419).
  - A shared page kit in `apps/web/src/ui`: page container and header, status chip with the stop reason in words, confirm dialog, empty state, error banner, skeletons, a list that is a table on desktop and cards on phones, and date, relative-time and cost formatting in the profile's time zone.
  - Every destructive action asks through the same confirm dialog; no `window.confirm` remains. Deleting a task or a schedule now asks first.
  - The run page is its own file with a back link to Runs. The agent policy, model tier, ceiling and pricing pages use the kit.
- **Runs API: paging, filters, search and counts** (#420).
  - `GET /runs?envelope=1` returns `{ items, nextCursor }` with keyset paging. Filters: `status`, `state`, `taskId`, `trigger`, `from`, `to`, `q`, `stopReason` and `policyId`. Without `envelope` the answer is the array it always was.
  - `GET /runs/counts` returns the total, the live count, a count per status and the cost of the filtered set.
  - List rows carry `taskName` and never the transcript or the policy snapshot.
  - `npm run seed:runs --workspace=api` fills a development account with finished runs.
- **Documentation for agent run policies** (#410). These documents now describe policies as the way to control a run:
  - VISION §25–§27, plus the root and console READMEs;
  - the operations and capacity runbooks, including a "run that seems to burn tokens" checklist;
  - the API reference, including the `hexactra.agent-policies` v1 file format and the run fields;
  - the security guide, the MCP and agent-framework guides, and `console/AGENTS.md`.

  The policy routes now have OpenAPI summaries.
- **Run budget meter and cost-aware alerts** (#408).
  - **Run page:** shows the run's policy, tier (highlighted when escalated) and model. A live budget meter has one bar per limited budget, ∞ for an unlimited one, and warning and error colours. It shows "≥" for a cost that is not fully known, and why the run stopped together with the agent's summary.
  - **Run timeline:** routing steps (↑, ↓ and ⇄) appear in it.
  - **Runs list and task cards:** the runs list shows cost and stop reason. Task cards show 30-day spend and the average cost of a successful run.
  - **Alerts:**
    - `hexactra_run_budget` gains a cost threshold.
    - New `hexactra_run_stalled`, with a starter rule.
    - New `hexactra_run_cost`, a per-run cost limit with a starter rule that is created disabled.
- **Agent policies in the web console** (#407).
  - Settings → Browser agent → Agent policies lists the built-in and personal policies, with their tiers, budgets, usage and version. From there you can create from a template, duplicate, edit, set the default, export, import and delete with reassignment.
  - The full-page policy editor has a "No limit" switch for every budget and warns when nothing would stop a run.
  - Model tiers page for each user. Admin pages for deployment model tiers, budget ceilings and model prices.
  - The task form picks a policy, schedules can override it, and "Run with…" runs a task once under another policy. Task cards show the policy and the model.
- **Agent policies in MCP, the SDK and the CLI** (#409).
  - MCP: new tools `policies_list`, `policy_get`, `policy_create`, `policy_update`, `policy_set_default`, `policies_export` and `policies_import`. `policy_id` is accepted on `run_goal`, `task_create`, `task_update`, `task_run` and `schedule_create`.
  - SDK: typed helpers `hx.policies`, `hx.tasks` and `hx.runs`, plus the `AgentPolicySpec` type.
  - CLI: `policies list|show|export|import|default`, and `--policy` on `runs start`, `tasks run|create|update` and `schedules create`.
  - Runs show their policy, tier, cost and budget use in the CLI and the TUI.
- **Stall detection, tier escalation and provider fallback** (#405).
  - Stall detection is always on, including under the Unlimited policy. It watches for consecutive failures, a repeated action, no progress and idle rounds.
  - The policy's `onStall` response decides what happens: nudge, then escalate to a stronger tier; escalate at once; ask a person; or stop as `stalled`.
  - Escalation switches model tiers only between chunks, and the run returns to its start tier after 5 progressing actions.
  - A provider outage or rate limit retries the chunk once on the tier's fallback model.
  - Routing steps show in the run timeline. Runs carry `currentTier` and `escalations`.
  - Fixed: an unavailable provider is no longer mistaken for a model that refuses images.
- **Context efficiency follows the run's policy** (#406).
  - Settings: `callsPerChunk`, `observationChars`, `screenshotsKept` and `pruneBatch`.
  - Screenshot window: the model sees the last few screenshots. Old ones are pruned in batches, so the provider's prompt cache keeps hitting, and only their hashes are stored.
  - Stable prompt: instructions and tool definitions stay byte-identical across runs, and the round input puts its stable parts first.
  - New metric `app.runs.input_tokens_per_call`.
  - On a scripted 30-action fixture, the Balanced settings use 18% fewer input tokens than the old fixed settings.
- **The budget engine enforces every run budget** (#404): actions, model calls, active minutes, input tokens, output tokens and cost. `null` means unlimited.
  - Ceilings: administrators set deployment ceilings in `browserAgentCeilings`, and they clamp every policy. A run's effective budget is fixed in its snapshot.
  - Warning: a run gets one warning per budget at `warnAtPercent`.
  - Wrap-up: when a budget is used up, the model makes one final call to report what it achieved, so a stopped run still returns a partial result.
  - Stop reason: runs carry a typed `stopReason` (`finished`, `budget_*`, `stalled`, `cancelled`, `error`, `no_model`) and a `budget` view (effective, used, percent, source).
  - Alerts now count budget stops by `stop_reason`. The hidden chunk cap is gone.
- **Model tiers: Fast, Standard and Frontier** (#403).
  - Where they are set: the `browserAgentTiers` system setting (deployment default) and `tiers` in the user's `browserAgent` setting (per-user override). Each tier is a model, a reasoning effort, an output cap and a fallback model.
  - How a run picks its model: policy pin, then the user's tier, then the deployment's tier, then fill-down, then the user's default AI model. A run resolves its tiers once at start, and every model call uses its tier's model, effort and output cap.
  - Early checks: a run whose start tier has no usable model fails before a browser is allocated. A model without image input starts with screenshots off.
  - New route `GET /api/agent-policies/model-tiers/effective` shows each value and where it came from. The console binds the platform's `AI_TARGET_RESOLVER` for the browser agent.
- **Agent policies export and import as JSON** (#402).
  - `GET /api/agent-policies/export` (`ids`, `includePins`) returns a portable `hexactra.agent-policies` v1 file. It carries no ids, user or secrets.
  - `POST /api/agent-policies/import` takes `onConflict` set to `rename`, `skip` or `replace`. An import is atomic. Model pins this deployment cannot use are dropped with a warning, and budgets above the deployment ceilings are flagged.
- **Agent policies** (#401): named, versioned, personal bundles of model tiers (with optional per-tier model pins), budgets where each may be unlimited (`null`), stall detection and context settings.
  - Four built-in policies: Economy, Balanced (the default), Thorough and Unlimited.
  - API: `GET/POST/PATCH/DELETE /api/agent-policies` (with `If-Match`, duplicate, `reassignTo`) and `GET/PUT /api/agent-policies/default`.
  - Tasks, schedules and run starts take a `policyId`. Every run snapshots its policy at its first step, so editing a policy never changes a live run.
  - The runner takes its action and active-minute limits from the snapshot.
  - Deprecated: the task fields `maxSteps`, `maxMinutes` and `model`. They still work for one release, map to a derived "Task: <name>" policy and return a `Deprecation` header. Existing tasks were converted by the migration.
- **Every model call the browser agent makes is priced** (#400). Admins set USD prices per million tokens (input, output, cached input) in the `agentPricing` system setting. Runs report `modelCalls`, `cachedInputTokens`, `costUsd` and `costKnown` (false, and shown as "at least", while a model has no price). Tasks report their 30-day `spend30d`. The platform's AI usage report is priced too. New metrics: `app.runs.model_calls`, `app.runs.cost`.
- **A run's time budget counts only active time** (#399). Time spent waiting for a person no longer makes a resumed run fail with "Time budget exhausted" (`runs.active_ms`). Task defaults are now 100 steps and 30 minutes everywhere; before, a task created outside the API got 40 and 15. A run that works longer than one job's runtime limit continues in a new job ("Run continued in a new job") instead of being reaped.
- **The bundled VPS browser host is opt-in** (#343). New deploys leave it off; an existing deploy that runs it keeps it (`COMPOSE_PROFILES=bundled-host` in `infra/compose/.env`). Its desktop now opens in the console through the fabric tunnel, like a node's. The old ticket viewer (`/viewer/local/`, `POST /api/fleet/viewer-ticket`, `HEXACTRA_VIEWER_PASSWORD`) is removed.
