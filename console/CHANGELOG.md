## [Unreleased]

### Added

- **Export a run as a JSON trace file** (#542, console 1.59.0): `GET /api/runs/{id}/export?format=json&screenshots=embed|none` answers one `hexactra.run-trace` file (`formatVersion` 1) with the run, its policy, budget and models, every step with its question and answer, the masked trace screenshots (base64, or left out with `screenshots=none`) and the run's chat. Every string is masked at export time (`masking.hits` counts what was); never the transcript, a token, a withheld answer or an AI app's grant. 50 MB at most (`413 EXPORT_TOO_LARGE`), 10 a minute per user (`429 EXPORT_RATE_LIMITED`); audit event `runs.exported`, counter `app.runs.exported`. Also `hexactra runs export <id> [--no-screenshots] [-o <file>]`, `hx.runs.export(id)` in the SDK with the file's JSON Schema (`packages/sdk/run-trace.schema.json`) and an example, and the read-only MCP tool `run_export` (the trace without images, cut to the result limit with `truncated`). Docs: `docs/runs.md` ("Exporting a run").
- **Every run keeps a trace** (#541, console 1.58.0): the questions it asked and the answers given (`handoff` steps with `action: "answered"`), the owner's chat guidance (`guidance` steps), a closing `end` step, and masked screenshots of the key moments (asked, before and after a confirmed step, a stall, the end) in object storage. `GET /api/runs/{id}` steps gain `hasScreenshot`, `screenshotMoment`, `screenshotMasked`, `screenshotNote`, `questionId` and a masked `question`; the picture is `GET /api/runs/{id}/steps/{seq}/screenshot`. Needs the fabric and the extension of #539 for pictures. Docs: `docs/runs.md` ("What a run records").

### Changed

- **The confirmation gate decides by what is clicked, not by the model's words** (#550, console 1.59.1). With "Ask me before purchases" on, a click is stopped only when its target commits something (a button, submit input, link or menu item labelled "Pay", "Send money", "Place your order", "Confirm transfer", "Delete account", …, or a submit button whose form posts to a commit path), read from the page through the fabric; the model's `reason` and the selector are no longer inputs, so choosing a date "for the payment" no longer asks. The paused step stores `{ category, label }`, the confirmation that follows carries a server-set `gate: { host, category, label }` (new on question views), and an approval lets through that target only. Docs: `docs/questions.md` ("The confirmation gate").
- **`screenshotKey` is no longer returned on run steps** (#541). It was never set; a step now says `hasScreenshot` and the picture is served by its own route.

- **Platform 0.1.0-next.39: a client's connections on the OAuth clients page** (#535, console 1.55.2). Administration → OAuth clients → a client → **Details** now lists every user's connection to that client (scopes, organization, connected, last used, active or revoked with the reason) and revokes one after a confirmation, next to the existing **Disconnect** on External AI apps. Also from the platform: a deterministic storage conformance check and a longer registry wait in its releases.

### Fixed

- **Per-address limits count each caller again behind the stack's nginx** (#530, console 1.54.1). The API built Fastify without `trustProxy`, so every caller reached it from nginx's container address and the unauthenticated MCP limit and the platform OAuth server's authorize and register limits shared one bucket for everyone. New deployment variable `TRUST_PROXY` (`infra/compose/app.env.example`): empty (the default) trusts loopback, link-local and private ranges, `false` trusts no proxy, otherwise a comma-separated list of IPs or CIDRs; `true`, a hop count (Fastify 5 ignores one) or a malformed entry stops the API at boot. New Doctor check `mcp.trust_proxy` warns when it is `false` while `APP_URL` is public HTTPS. Docs: `docs/runbooks/public-exposure.md` section 4, the README "Enable it" checklist, `docs/mcp.md` "Rate limits".
- **The browser's picture stays while a run waits for you** (#525, console 1.53.1). The fabric took no screenshot while the agent waited for an answer or a person held the desktop, so the chat's Browser card and an approval's page went blank (for example after switching apps and back). A plain screenshot is now taken in those moments, except while a code or password is being asked for. Needs the fabric redeployed.

### Changed

- **Platform 0.1.0-next.36, and the console uses its new seams** (#520, console 1.52.1). The MCP endpoint tells "ask for more access" from "not allowed" with the platform's `userPermissionsOf` (EnterpriseAppBase #1194) instead of re-deriving the permissions from platform internals, and the admin **Disconnect** of a user's AI app calls the platform's `revokeGrantAsAdmin` (EnterpriseAppBase #1195). ### Added

- **ChatGPT's step-up form** (#531, console 1.55.0). When ChatGPT calls a tool its consent does not cover, the console now answers with a tool error result carrying the sign-in challenge in `_meta["mcp/www_authenticate"]` (OpenAI's documented form) instead of the HTTP `403`; Claude and every other app keep the `403`. ChatGPT is recognised by its OAuth client's hosts (`chatgpt.com`, `openai.com`) or its `clientInfo.name`. A new admin setting, Administration → External AI apps → **How an app asks for more permission** (`mcp.stepUpForm`: `auto` by default, `http`, `tool`), forces either form for every app. The refusal is recorded in the activity as before.
- **One sign-in card, with "remember me"** (#527, console 1.54.0). The agent asks for the username and password together in one card (the phone's password manager can fill it), instead of two cards. When the site offers "Keep me signed in" or "Trust this device", the card shows it, ticked by default, and the agent sets the site's box as you chose. New question input `credentials` and option `rememberLabel`; the fabric gains the `credentials` handoff and a `remember` option. Needs the fabric redeployed with the console. Details: README, "Chat"; `docs/questions.md`.
- **Sign in from the chat** (#524, console 1.53.0). When a site needs a sign-in, the agent asks for the username and then the password as cards in the thread (or in the Inbox for a task's run) and signs in itself, instead of asking you to do it in the remote browser. Details: README, "Chat".
- **One rate limit across several API replicas** (#517, console 1.52.0, post-v1). `MCP_RATE_LIMIT_STORE=postgres` (new deployment variable in `infra/compose/app.env.example`; default `memory`, any other value stops the API at boot) counts the `/api/mcp` limits and the platform OAuth server's limits (`OAUTH_RATE_LIMITER`) in a shared table, so N replicas no longer allow N times each limit. A sliding window counter (one row per key and minute, the previous minute weighted by its share still inside the sliding minute), counted in one `INSERT … ON CONFLICT DO UPDATE … WHERE` statement that re-checks the limit under the row lock. New app table `rate_limit_windows` (migration `20261118134227_rate_limit_windows`; run `npm run prisma:migrate`), cleaned by the new hourly job `mcp.rate_limit.purge` (its `@Cron` only enqueues, only with `postgres`). Failure keeps today's rule: authenticated MCP callers are let through, unauthenticated ones (and the OAuth endpoints) get `429`. No Redis. The in-memory limiter stays the default for one process. Docs: `docs/mcp.md` "Rate limits"; `docs/runbooks/public-exposure.md` section 4, which also explains `trustProxy`: the API does not set it, so its per-address limits share one bucket behind the stack's nginx.

- **The browser keeps a run on its allowed sites** (#508, console 1.51.0). A run, a chat or an AI app with allowed sites now opens its browser session confined to them: the browser itself blocks every top-level page on another site, including the ones a page opens on its own (a redirect, a script, a pop-up), so prompt-injected content cannot walk the agent elsewhere. Each blocked page shows in the run as a **navigation_blocked** step (the host only, never the URL) and the agent is told. The task's sites and the app's are intersected, and two lists with nothing in common allow nothing. A confined session cannot use the desktop tools, since desktop input reaches every window. Needs a fabric and an extension from this release; older ones ignore the list, and the console still checks every navigation the agent asks for. Fabric: `allowed_domains` on `POST /v1/sessions`, `navigation_blocked` on operations, the `session.navigation_blocked` event, `hexactra-fabric session create --allow-domain` ([docs/remote-control-api.md](../docs/remote-control-api.md#allowed-sites)).

- **Scope-gated MCP tools and step-up consent for OAuth apps** (#460, E33.2, console 1.42.0): an app signed in with OAuth sees and can call only the tools its consent covers, and asks the user for more when it needs it. Details: `docs/mcp.md`, "What a connected app can do" and "Asking for more".
  - **The gate** (`apps/api/src/mcp/mcp.access.ts`): for an `oat_` token each tool is `allowed` (the token holds its scope and what that scope requires: `browser:evaluate` and `desktop:control` also need `browser:drive`), `needs_scope` (the user's role gives the permissions, so re-consent can add the scope) or `forbidden` (it cannot). Sessions, personal access tokens and device tokens are not gated: their `tools/list`, calls and `instructions` are unchanged, byte for byte.
  - **`tools/list`** gives an OAuth app its callable tools plus, while the new system setting **`mcp.advertiseStepUpTools`** is on (default), the step-up ones, marked "Needs extra permission: the user will be asked to allow it."; `forbidden` tools are never listed. Every tool, for every caller, carries `securitySchemes: [{ type: 'oauth2', scopes }]` (ChatGPT's per-tool auth; the shape is unverified until E33.10).
  - **Step-up**: a `tools/call` that needs a scope answers the whole HTTP request `403` with the platform's `WWW-Authenticate: Bearer error="insufficient_scope", scope="<granted> <missing>", resource_metadata=…` and `{"error":"insufficient_scope",…}`, before the tool runs (a batch mixing it with allowed calls is refused whole). Re-authorizing with that scope shows only the new scope on the consent page and the grant then holds the union. A `forbidden` call is a tool error ("Your Hexactra account is not allowed to do this. Ask an administrator."), HTTP `200`. A token that stops being valid during a call answers the whole request `401` with the `invalid_token` challenge.

### Changed

- **MCP, for every client** (#462): tool errors are no longer the raw REST string (`"403 FORBIDDEN: …"`) but a sentence with the code in parentheses where it helps (see `docs/mcp.md`, "Errors"); `run_status` returns the latest 20 steps by default (was 10) plus `olderSteps`; `browser_elements` returns 200 elements by default (was a fixed 80); `browser_text` returns up to 20,000 characters by default (was 8,000); results from web pages start with the untrusted notice; and on `2025-06-18` and later the text block of a structured tool starts with a summary line before the JSON (read `structuredContent` instead of parsing the text). `policies_export` is in the `runs:read` scope: it only reads.
- A run's time budget counts **active** time only. Time spent waiting for a person no longer makes a resumed run fail, and a run that outlasts one job continues in a new job.
- A run's limits come from its agent policy: the default Balanced allows 60 actions, 120 model calls, $2 and 20 active minutes (the earlier task default was 100 steps and 30 minutes). Existing tasks keep their limits through a derived `Task: <name>` policy created by the migration.
- The goal runner picks every model call's provider, model, reasoning effort and output cap from the run's resolved tiers, no longer from the task's `model` or the user's default model alone. A run with no usable model fails at once, naming the tier, before a browser is allocated.
- The documentation (`VISION.MD` sections 25 to 27, the console README, runbooks, API, security and MCP guides) describes policies instead of per-task step and time limits.

### Deprecated

- The task fields `maxSteps`, `maxMinutes` and `model`. They still work and map to a derived personal policy (`Task: <name>`), and the response carries a `Deprecation: true` header. Use `policyId` instead. **They are removed in the release after the one that introduced agent policies.**
