# Client parity: what hosted AI apps (E33) added

What each client can do with the capabilities of epic E33 (#458): connected apps, `run_wait`, the run origin filter, the MCP activity log, the kill switch, the in-chat cards and consent. "No" is a decision with its reason; nothing here is left for later unless it names an issue. The earlier tasks, schedules and runs capabilities are in [api-tasks-runs.md](api-tasks-runs.md#client-parity). The machine-checked form is [packages/shared/capabilities.json](../packages/shared/capabilities.json): `apps/api/test/capabilities.db.spec.ts` (REST, MCP), `apps/cli/src/capabilities.test.ts` (CLI, TUI) and `apps/web/src/__tests__/capabilities.test.ts` (web) fail when a surface drops a value it names, or when a route, command or tool belongs to no capability. The registry has no Android column: the Android app is a Trusted Web Activity around the web app, so a page that exists on the web exists there (see [the Android column](#the-android-column)).

## What secrets added (E37)

**No MCP tool reads or manages a secret, and none ever will without a decision recorded here.** That covers the provider connection, the Activity list, the logins reached, the identity items, the cards, and the settings and limits that decide whether the agent may use them: a hosted AI app must not be able to find out what the owner saved, rewire where it is kept, or widen what the agent may use. The only MCP tool that touches a secret is `browser_type_secret`, which types what the owner entered on the signed-in console page (a handoff) without the model seeing it. Each row below says so with its reason; `packages/shared/capabilities.json` carries the same decision and `apps/api/test/capabilities.db.spec.ts` checks it; the threat model is [security-secrets.md](security-secrets.md).

## What connections added (E39)

**No MCP tool lists, adds, changes or uses a connection.** Hosted AI apps (ChatGPT, Claude) cannot see which accounts the owner connected, connect one, switch what it may do, or call it: they reach a connection only through a run the owner set up, under the rules of E39.7 ([connections.md](connections.md#what-the-agent-can-do-with-a-connection-e397)): a task or chat must be told to use it (`connections` on `POST`/`PATCH /api/tasks` and `/api/chats`, which no MCP tool takes), the app's limit `allowConnections` must be on (default off, so `run_goal` and `task_run` of a task that lists connections give the run none otherwise), calls that send or change are gated by saved approvals and a card a hosted app cannot answer, and every call names the account. The tools (`connections_list`, `mail_*`, `calendar_*`, `docs_*`, `sheet_*`, `file_upload`) are the runner's own and exist on no MCP surface. A personal access token can list, test, pause and remove (the CLI); it cannot connect an account, because the consent is a browser flow.

## The Android column

The Android app opens the console in a Trusted Web Activity, so every page above is there.

**Proven without a device** (`apps/api/test/android-links.spec.ts`, #516):
- the app's one verified `https` VIEW + BROWSABLE intent-filter names the console's host and no path, prefix or pattern, so `/oauth/consent?request=…` and `/settings/ai-apps/:clientId` are both in it;
- the `app.connected` and `app.scope_added` notifications link to the same-origin path `/settings/ai-apps/:clientId`, which the app opens in itself.

**Only a device can check** (#516):
- that Android's link verification succeeded for your console's host (`/.well-known/assetlinks.json`, served by the Android slice; Administration → Android app shows the fingerprints);
- how a vendor's mobile app opens the sign-in. Most open it in an in-app browser tab, where app links do not apply. That still completes the consent: the tab uses Chrome's sign-in cookies, so a person signed in to the console in Chrome (the app runs on Chrome too) sees the consent page directly; otherwise they sign in first. **Allow** returns to the vendor's app through its own callback.

Until a device check is recorded on #516, treat the consent page as "opens in the app or in a browser tab, and either completes it".
