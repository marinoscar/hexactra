# Security: the Knowledge Graph

The threat model of the Knowledge Graph in a Hexactra Console deployment (epic E46). Related documents:

- [the owner guide](knowledge-graph.md) and the [decision record](decisions/knowledge-graph.md);
- the package's own threat model, [packages/hexactra-kgraph/docs/security.md](../packages/hexactra-kgraph/docs/security.md), which covers what the package enforces for any host;
- [security-hosted-clients.md](security-hosted-clients.md) for MCP and hosted AI apps in general.

## What is at stake

A procedure is replayed without the model. If an attacker could write into one, every later run of that task would do what they want, quietly. The agent works with its owner's full powers (VISION §27), so a poisoned procedure could send mail, pay or sign in wherever the owner can. The graph also must not become a place where secrets collect.

The feature ships **off** at the deployment, user and task levels, and a chat or one-off run also needs the owner's everyday switch (off by default). With any level off, no capture, replay, job, agent tool or MCP tool runs, and `apps/api/test/runner-characterisation.db.spec.ts` passes unchanged.

## Trust boundaries

| Source | Trusted for |
|---|---|
| The owner, signed in to the console in a browser session | Approving a sensitive change or an import; switches; restore, forget and delete. |
| The server's own records of a run (tool names, argument values compared with the run's parameters and earlier results, post-state) | Building a procedure. |
| The run's own limits (allowed sites, connections, recipients, saved approvals, confirmation settings) | Every gate decision, during replay as well. |
| Web pages, emails, files, MCP tool descriptions and results, model output, an imported file | Nothing. They are data. |
| A personal access token, an OAuth app (MCP, ChatGPT, Claude), the CLI, a node credential, a webhook | Reading, starting an ordinary run (`procedure_run`) and proposing a site fact (`site_fact_propose`, always `proposed`). Never approving a change or a fact. |

## Threats and controls

| Threat | Control | Where it is enforced |
|---|---|---|
| A page, an email or an MCP tool result tells the agent to add a recipient, a site or a step, hoping it is learned | A procedure is compiled only from server-recorded facts (tool names, argument provenance, post-state), never from model text or page prose. A repair that adds or changes a send, a payment, a recipient, a site, an account or a credential is **sensitive**: it waits for the owner's review and is never replayed before it is approved. | `packages/hexactra-kgraph/src/compile/`, `src/repair/classify.ts`; `apps/api/src/kgraph/kgraph-compile.service.ts`, `reviews.service.ts`; `apps/api/test/scenarios/kgraph/poisoning.spec.ts` |
| A judge step is used to smuggle an instruction | A judge step has no free-text instruction field (strict schema, validator rule `judge_instruction`). It gets the owner's goal, its declared inputs (as data) and a fixed output schema. An answer outside the schema is a failed check. | `src/schema/step.ts`, `src/validate/validate.ts`, `src/execute/execute.ts` |
| Secrets end up in the graph | Argument provenance keeps a value only as a literal that is structural or the goal's own words, and that passes the console's sensitive-pattern table. A secret-looking value is `withheld` and its step stays with the agent. Saved logins are referenced by label. Validator rules `sensitive_literal` and `sensitive_flow` (no secret to a judge or to an account or MCP tool). Exports hold no ids, tokens, evidence or traces. | `src/compile/trace.ts`, `src/validate/`, `src/transfer/`; `apps/api/src/runner/host/kgraph/observer-port.ts` (console sensitive table); `kgraph-capture.db.spec.ts`, the package's `transfer.spec.ts` |
| A label or a literal shown in a page, the CLI or an MCP result carries secret material or page text | Every label and literal passes the run trace's masking before it leaves the API. A saved login is its kind and label; a sensitive parameter is its name. `procedure_get` starts with the untrusted notice and sets `untrusted: true`, because step labels can come from web pages. | `apps/api/src/kgraph/kgraph-read.service.ts`; `apps/api/src/mcp/mcp.tools.ts` (`procedure_get`) |
| A replay bypasses Stop, Pause, the gates or crash safety | Every replayed call goes through `executeTool`: Stop, Pause, the site and risk gates, saved approvals, the span, intent recording and the step row. A commit-class step whose outcome is unknown after a crash is never sent again. A verification run asks the owner before every commit-class step, whatever the task's settings and saved approvals say. The model-located recovery rung is never used for a commit-class step. | `src/harness/index.ts`, `src/execute/recovery.ts`; `kgraph-replay.db.spec.ts`, `kgraph-verify.db.spec.ts` |
| A sub-procedure widens a run | `run_procedure` walks only another **active** procedure of the same owner, never the task's own, at most one level deep, with every step through the run's own wrapper and gates. | A review is answered by something other than the owner | The answer route requires a signed-in browser session (`principal.credential === 'session'`). A personal access token, an OAuth app (MCP, hosted AI apps), a node credential or a device token gets `403 KGRAPH_REVIEW_CONSOLE_ONLY`. There is no MCP tool, webhook or CLI command for it. | `apps/api/src/kgraph/reviews.controller.ts`, `reviews.service.ts`; `kgraph-reviews.spec.ts` |
| A hosted AI app changes or runs more than the owner allowed | Over MCP there are three procedure tools only (and the two site-fact tools, below): two reads (`procedures:read`) and `procedure_run` (`procedures:run`), which runs only an active procedure of a task in `reuse` mode and starts an ordinary run through `POST /api/tasks/{id}/runs` with that run's own policy, limits and gates. Both scopes are opt-in at consent. The tools are listed and callable only while the deployment and the caller's own switches are on. A sensitive parameter is never accepted from a caller. Nothing over MCP creates, changes, approves, restores, forgets, exports or imports a procedure, or changes a switch. | `apps/api/src/mcp/mcp.tools.ts`, `mcp.scopes.ts`; `mcp-manifest.spec.ts` |

Who proposed it (the credential kind and the OAuth client) is in the audit row. Both scopes are opt-in; both tools are listed and callable only while the deployment and the caller's switches are on. The file is bounded (1 MB, 50 procedures, 500 steps each) and its patterns are length-limited and refused when they nest quantifiers. | `apps/api/src/kgraph/transfer.service.ts`, `src/transfer/`, `safePattern` in `src/execute/execute.ts`; `kgraph-transfer.db.spec.ts` |

## What an administrator decides

- **Whether to allow it at all** (`kgraph.enabled`, off by default). Turning it off stops everything at once and deletes nothing.
- **Audit and suspension** (`auditEvery`, default 10; `suspendAfterFailures`, default 3). A lower `auditEvery` catches drift sooner, at the cost of more AI-only runs.
- **Retention** (`retentionDays`, default: keep). A number retires procedures not run for that long, and upkeep prunes their traces.
- **Pacing** (`human` by default). `fast` drops the pauses between replayed browser actions. It is meant for account-only procedures and tests; it can make a site more likely to flag the session.
- **Who has the permissions.** `kgraph:read` and `kgraph:write` go to contributors and organization administrators by default (`kgraph:read` to viewers too). `kgraph:admin` goes to system administrators.

## Residual risks

- An owner who approves a site fact proposal accepts its words as data for later runs. A proposal that reads harmless ("Reports are under Account, then Exports") may still have been steered by a page, an email or an MCP result; it cannot widen anything, but it can mislead the agent about the site. Read the proposal and its evidence (the run it came from) before approving.
- The instruction-shaped text check is a list of patterns, defence in depth behind the owner's approval: a proposal phrased without them reaches Reviews.

- An owner who approves a sensitive review without reading it accepts its changes. The review shows each change in plain, masked words.
- A site can change so that the same control means something else, which can mislead element re-resolution. Exactly one visible match is required, commit-class steps never use the model-located rung, and outcome checks and audit runs catch silent drift after the fact.
- A structural repair (a moved button, a new path on a known site) is promoted after one clean verification run, without a review. It cannot add a send, a payment, a recipient, a site, an account or a saved login, because those make the change sensitive.
- The sensitive-pattern table is pattern-based. A secret with no recognisable shape that also appears word for word in a task's goal could be kept as a literal. Do not put secrets in a goal; use a sensitive task parameter or a saved login.
- The agent-framework recipes for Hermes, OpenClaw and Pi were not run against the procedure tools, and no test checks the OAuth consent screen with the switch off (#796).
